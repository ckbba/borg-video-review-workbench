# 视频复刻与拾影接入 Agent：初步架构建议

> 调查范围：复刻代码、16 个落盘任务、案例复盘、拾影后端与草稿结构、已有自动配对实验。没有逐条播放所有视频，也没有独立完成图像质量验收。以下区分记录事实、推断和待验证建议。

## 1. 结论

建议在现有能力之上增加 Agent 调度层，逐步开放决策点。保留已经有效的复刻方法、媒体处理和人工编辑入口。Agent 负责理解目标、组合能力、选择下一步；代码负责输入约束、提交、记账、落盘和恢复。

首期采用一个主 Agent，调用视频复刻、拾影、媒体处理等能力工具。暂时没有证据表明需要多个长期角色 Agent，也不需要先重做完整工作台。

## 2. 当前版本修正：SAM 2.1 Small

用户已确认拾影升级到 SAM 2.1 Small。重新读取当前 sam_worker.py 后确认：加载、点选和框选路径均以 model_type.startswith('sam2') 分派，分别位于 21、59、82 行。因此，早期调查提到的 sam2_video 精确匹配问题已不适用于当前代码。

历史数据库里的 SlimSAM 蒙版和较早运行日志只说明过去使用的模型，不能据此断言当前仍使用 SlimSAM。本轮未重新执行分割推理或性能基准。

SAM 2.1 Small 负责选区边界；Agent 仍需负责选对对象、配对源与目标、保护遮挡物，并检查结果。分割升级不会自动带来精确排版能力。

## 3. 复刻工程里值得保留的资产

- 场景关键画面锚定、原片动作与时间结构保留。
- 视频切段、重定时、接缝检查、拼接、回原声。
- 图像/视频 provider 抽象与价格计算。
- 商品实拍素材库，以及已知商品细节问题进入后续验收的机制。
- 逐段重做、独立重合成、配音与画面解耦。
- 任务产物、提示词、参考图、质量报告和费用记录。

当前编排已经混合了规则与 LLM 判断。Agent 接入的增量在于：可根据观察结果改变步骤、选择不同能力、询问缺失信息，并在重试无效时调整策略。

## 4. 真实记录能说明什么

对 16 个任务的 costs[].yuan 求和，9 个任务有正金额，合计 265.11 元。这是落盘字段合计，不是完整账单；LLM 等成本未完整纳入，不应据此推导生产均价。

领克任务 20261107-9e2576 记录金额 45.28 元，5 张关键画面合计 12 次尝试，4 个视频段合计 8 次尝试。说明重试决策值得优先研究，但这些次数本身不能证明重试无效。

20261106-14b8a3 等任务包含 mock 产物或重启中断，不能当作真实模型质量失败样本。历史任务还可能使用旧版流程，不应直接按当前 simple/full 路由归类。

案例复盘明确记录了商品角度不足、三视图编造细节、验收遗漏等问题。Agent 应区分“缺少事实素材”和“当前生成方法失败”，避免对两者使用同一种重试策略。

开始前确认、生成结束、人工重合成之间的时间间隔可以作为流程分析线索，不能直接等同于人的实际操作耗时或必须等待时间。

## 5. 建议的架构与工具粒度

```text
用户目标、商品资料、参考片
             ↓
主 Agent：规划 → 调用能力 → 看证据 → 决定下一步
             ↓
视频复刻工具 / 拾影工具 / 媒体工具 / 素材库
             ↓
任务执行、成本约束、幂等、产物保存、恢复
             ↓
作品与可编辑工程；工作台展示进度、对比和人工干预
```

先开放中等粒度能力，例如“按原片制作复刻”“编辑这一张关键画面”“替换图片文字”“检查这一段”“重合成成片”。成熟的固定子流程可以继续作为一个工具执行。

仅暴露整条流水线会限制 Agent 的干预能力；一开始就把每个内部函数变成工具，则会增加调用与上下文成本。待实际案例证明需要介入时，再拆出单张关键画面、单段生成和单段检查。

每个工具至少声明：输入 schema、素材引用、执行模式、费用估计或未知状态、幂等键、任务 ID、产物引用、失败类型、证据。

代码继续强制执行供应商时长/图片数/提示词限制、用户预算授权、并发上限和状态校验。Agent 可在合法范围内选择策略，不能越过这些约束。

## 6. 拾影的“拖拽”可以怎样交给 Agent

当前拾影是编辑意图系统。源图、源蒙版、目标蒙版、归一化锚点、局部要求构成 mapping。前端拖拽负责收集这些数据，后端编译为参考图与生成指令。

provider.py 明确说明：坐标是自然语言中的区域描述，不是模型的精确控制参数。当前 mapping 没有旋转、图层层级等传统画布属性。

因此建议直接调用接口创建 mapping：

1. 视觉模型提出对象或粗框。
2. 调用 SAM 2.1 Small 得到候选选区。
3. 展示并检查源、目标蒙版叠加图，确认没有误选人物、手或背景。
4. 保存编辑关系，校验冲突。
5. 查看 reference-preview，核对实际参考输入。
6. 提交生成并对比结果，需要时调整选区或要求。

reference-preview 展示的是送入模型的参考图，不是最终构图预览。可补一张本地“选区与配对示意图”，辅助检查对象关系；它同样不能预测生成结果。

已有 auto_drag.py 已经实现“识别 → 模型配对 → 分割/多边形 → mapping → 生成”。日志记录 5 个场景、每个比较自动配对与整图引用两种路径，共 10 次任务成功。这里只能确认请求链路成功，不能宣称自动配对更准，或某种裁剪策略普遍更好。

应保留两种工具路径，让 Agent 根据场景选择：

- 整体替换、参考图主体明确：整图参考可能更简单。
- 多对象、遮挡、局部替换：选区 mapping 提供更多约束。
- 精确字号、字体、位置与图层：需要确定性排版/合成工具；仅增加 prompt 字段不能保证精度。

## 7. OCR 的价值与边界

当前 OCR 使用本地 RapidOCR，返回文字、归一化 bbox/polygon、置信度和 needs_review。可以复用为素材理解与文字定位工具。

Agent 可以根据识别结果构造 text_edits，再交给拾影生成改字。生成后再 OCR 核对文字内容，并检查周边画面。OCR 定位成功不等于最终改字一定正确，字体与背景保持仍需验收。

## 8. 为未来扩展准备的最小基础

### 素材命名引用

内部用 asset_id、角色和来源关联素材；最后由 adapter 按实际输入顺序编译成 @imageN。这样动态补图不会要求 Agent 自己维护序号。

### 能力描述

集中描述 provider 的时长、参考图数、文字长度、音频支持、价格与输出限制。已有 provider 属性可以逐步整理，不必先做通用框架。

### 持久任务记录

当前 recoverJobs 对部分运行中任务标失败，resumeReplica 会清空 segments。接入长任务 Agent 前，应记录每次提交的请求 ID、状态与产物；遇到状态未知的付费请求先核对，避免重复提交。

### 产品经验与评测

把经验整理成带适用条件的策略：案例、证据、适用商品、不可妥协细节、允许近似的部分。执行约束留在代码，策略可迭代。

选择实拍输入清楚的成功/失败案例做回放；mock 与真实生成分开。评价任务完成率、商品细节、动作保留、人工介入、费用和耗时。当前没有证据支持预先承诺节省多少成本。

## 9. 推荐下一步

选一个真实闭环：“用户要求复刻 → 发现某关键画面需局部替换或改字 → 调用拾影 → 检查并回到复刻链路”。先验证 Agent 能选择正确工具，并且产物可以在两个系统间继续编辑。

首个验证可使用已有任务与素材，先产生规划、配对和检查证据，再在明确预算下测试真实生成。旧流程继续可用，逐步比较 Agent 的判断与人的判断；通过案例后再开放更多自主步骤。
