# 一键换主角（swap）

面向用户的页面：选模板 → 传一张图 → 选预览图 → 拿视频。和复盘工作台共用一个 dev server。

- 用户页：<http://127.0.0.1:5173/swap.html>
- 复盘工作台：<http://127.0.0.1:5173/>（不受影响）

## 链路

```
检查图片（Guard）→ 生成 2 张预览图（ImageEditor）→ 用户选一张
→ 视频编辑（VideoEditor，最多同时 3 个任务）→ 自动质检（Checker）→ 剪掉结尾跑偏的帧，放回原声 → 对比视频
附加版本（动漫 / 3D / 夜景…）在“替换后的结果”上再改一次，一次只改一样东西
```

方法来自 Scenario 的 ALTER skill（`vendor/alter`，MIT）。提示词直接读它的 36 个预设，质检直接调用它的 `alter_check.py`。

## 一键复刻（主流程，`engine/director.ts`）

用户：选视频（模板或自己上传）→ 放 1–4 张图 → 可选写一句 → 一键复刻 → 下载。中间不用再操作。

```
看懂原片 → 制定方案（逐镜头：改 / 直接用原片；按场景分组；每个场景只出一张关键画面，选最清楚最正面的一帧）
→ 补全素材（原片需要、用户图里没有的角度才补，出一张多视图设定图并和原图比对）
→ 制作关键画面（第一张定基调，其余以它为锚）→ 全部关键画面一起验收，不合格的带修改意见重做
→ 分段同时生成（每段都锚定场景关键画面 + 素材，不用上一段尾帧，误差不累积；镜头内切开的段重叠 5 帧）
→ 检查修复（ALTER 动作检查 + 模型看外观 + 重叠帧 SSIM 看接缝；不合格的段带修改意见重做一次，留好的那次）
→ 合成（不用改的镜头直接用原片，重叠处交叉淡化，合回原声）
```

多颜色：原片里同款有几种颜色（或图案）时，方案里每种一个版本。出现最多的版本直接用用户的图，其余版本用用户的图改色，胸口图案保留用户的。同一段里有多种颜色时，提示词按秒写清每个镜头对应哪张图；每段最多 4 个场景（一次最多 5 张参考图），超了就在剪辑点拆开。

开始前确认（`stage: slots`）：方案和文案检查做完后，有用户才能定的事就停下，这时还没花钱：原片有多款、原片有用户图里没有的角度、文案里有看图确定不了的信息。每项都有默认值，可以直接开始；都没有就不停。换了图的款不再改色；补的角度图并入用户的图，那个角度不再生成；填的文案直接用进配音和字幕。

改动清单：方案模型读画面字幕，列出和新商品矛盾的文案（`replica.copy`）。看图能确定的直接改写；品牌、材质这类看图确定不了的改成通用说法，并标出来让用户确认。

配音和字幕（`engine/voice.ts`）：Whisper 听写 → 按改动清单改写 → edge-tts 逐句配音并压进原时长 → 叠加背景声 → 烧字幕。只动声音和字幕，不调视频模型。文案要改时，新任务的关键画面和视频都要求去掉原字幕；老成片的字幕是烧在画面里的，用模糊条盖住，花字盖不到。背景声现在是立体声消人声，只是临时办法；单声道原片没有背景声。环境变量：`SWAP_VOICE_PYTHON`、`SWAP_TTS_VOICE`、`SWAP_WHISPER_MODEL`、`SWAP_SUB_FONT`。

费用一律按 `src/pricing.ts` 的价目表算，不用 CLI 的扣费数字；被拒的任务记 0 元。历史任务用 `node swap/scripts/repriceCosts.mjs` 重算，原数字留在 `billedByCli`。

`SWAP_PLANNER=llm|basic`：方案和验收用多模态模型（`server/llm.ts`），borg / grok 时默认 llm；basic 不调模型（所有镜头都改、一张关键画面、验收全过），mock 演示默认 basic。模型调用失败会自动退回 basic，并写进日志。

## 商品库（`engine/products.ts`，数据在 `swap/products/`）

上传页选一个商品，这次的实拍图和补拍的角度就存进它，下次换别的视频直接选它，不用再传图。

- **只存实拍图和商品要点**，不存 AI 生成的设定图和改色图（生成图验收通过后仍可能编造细节，5 Nov 安踏）。关键画面也不存，它绑定某条原片的某一帧。
- **商品要点**是以前出过的错，手动添加。它会进方案和关键画面的提示词，并作为设定图、关键画面、视频段三处验收的不通过条件。任务开始时抄进 `replica.productNotes`，重跑时标准不变。
- 一个任务最多用 6 张实拍图（新传的优先）；没有设定图时，前 4 张进关键画面和验收。
- 目录独立于 `swap/data`，代码里不删文件：去掉一张图只是从列表移除。任务的 `uploads` 直接指向库里的文件，不要手动删 `swap/products`。

## 画幅

视频模型只接受宽高比 0.4–2.5：超出的自己上传的原片在看片时居中裁到 2.5。图片模型不支持 21:9（7:3）：这类片子的关键画面先加黑边到 16:9 生成，再裁回原比例。

关键画面全部没通过验收时任务停下，不生成视频，页面可选"仍然生成视频"（走 resume）。

## 验收和重做

关键画面按「target 看起来差不多」分场景：汽车的正面、俯视、背面、车内各出一张，没有对应画面的镜头模型会照原片画。

视频段的外观检查抽每个要改的镜头（最多 8 个）。只有明显错误（没换、型号或颜色错、畸形、多出参考图里的人）才自动重做，细节差异只记下来。

成片页可以只重做一段（`redoSegment`）：缺的关键画面先补，其他段不动，付费前弹窗确认。`refitFilm` 从已生成的原始片段重新合成，不调模型。合成时片段按比例放大裁切，不加黑边。

## 路线（`engine/route.ts`）

方案做完后判断一次，点开始后（确认页可能剪了镜头、补了图）再判断一次。下面任何一条成立就走完整路线，否则走简单路线；判断理由显示在确认页、结果页和链路复盘里。`SWAP_ROUTE=simple|full` 可强制。

- 方案模型没回答（基础方案）
- 原片里有 2 个以上的款
- 有 2 个以上的场景
- 时长超过模型单次上限 0.3 秒以上（只超一点的剪掉最后几帧）
- 有不用改、要保留原片的镜头
- 缺部位或有屏幕操作
- 有做不出来的镜头

**简单路线**：挑图 → 原片 + 挑中的图 + 一句话，整片一次生成 → 抽 3 帧检查外观，有问题只提示，不自动重做 → 合成，有口播才配音。不做设定图、改色、关键画面、分段。

**完整路线**：设定图 / 改色 → 挑图 → 关键画面（最多 3 轮）→ 分段生成 → 只有外观检查不过或接缝差才重做一次，两次都不理想时留动作分高的 → 合成 → 配音。ALTER 的结构和动作分只用来比较两次结果，不再触发重做。

两条路线共用：配音前丢掉 Whisper 没把握的句子（没有人声概率 ≥ 0.4，或 5 秒以上每秒不到 1.2 个字），没有可信口播就保留原声；文案检查不再把 Logo、水印当文案。

## 按镜头挑图（`engine/picks.ts`）

用户有 2 张以上的图时，开始花钱前由模型给每个场景挑最多 3 张（`replica.photoPicks`）。关键画面和视频段只用挑中的图，视频段跨场景时先给每个场景的首选。没有结果就按上传顺序。有设定图时实拍图排在设定图前面。模型发现的偏色、不同款只记在链路复盘里，还不会提示用户。

## 缺的素材和素材员（`engine/scout.ts`）

方案模型除了缺的角度（`views`），还会列 `needs`：`part` 是用户图没有、又推测不出来的部位（只有汽车外观，原片拍内饰）；`screen` 是屏幕上的真实操作。三类都放在 `plan.gaps`，在开始前确认页展示。

素材员是一个小 agent，在确认页之前运行，还没开始花生成费用。模型用自带的联网搜索找图，下载后亲眼看过才能选定；代码负责限制和校验。

- **在后台找**：确认页不等它，找到的图自动出现（页面在 `scouting` 时继续轮询）。点开始就停，之后不再写入图片；只有页面展示过且用户留下的图（`kept`）才会用。
- **上限**：8 轮、看 16 张图、6 分钟，见 `SCOUT`。只找部位（`part`），角度直接请用户补。上传页开关默认关闭。
- **没有生成工具**，失败也不影响任务。`SWAP_SCOUT=off` 可关闭。
- **屏幕操作不交给它**：菜单和功能是事实，只能由用户提供。
- **网图只看形状**：用户确认后进 `shapeRefs`，不算实拍图，不影响"够 3 张就不生成设定图"；商品库里标记为网图，下次可直接复用。
- 只下载公网地址，防止网页把服务器指向内网。

- **部位图**（`replica.partRefs`）：用户确认的内饰这类图，只给用到它的场景的关键画面，这个部位的结构和颜色以它为准；这些场景不用外观场景做锚点，也不进多视图设定图。

## 能不能复刻（`plan.shots[].fit`，`engine/trim.ts`）

方案逐镜头判断 good / rough / no，只看画面：no 只用于画面在演示真实屏幕界面、菜单操作的镜头，字幕口播里的功能宣传交给文案检查。有 no 时确认页显示比例条和三个选择：只复刻能做的部分（先把 no 镜头从原片剪掉，之后所有步骤都在剪短的片子上做，原片留在 `fullSource`）、全部都做、不做了（不花钱）。剪掉后口播会断开。

**还没做**：屏幕操作的合成和"不补时"的自动改片。确认页会明确提示这些镜头的屏幕内容不可信。内饰也还没有"重建"：关键画面仍按贴合替换来做，网图只作结构参考。

## 可插拔：四个部件，环境变量切换

| 环境变量 | 可选值 | 默认 |
|---|---|---|
| `SWAP_PROVIDER` | `mock`（演示、不扣费）/ `borg`（博观） | `mock` |
| `SWAP_IMAGE` / `SWAP_VIDEO` | 单独覆盖预览图或视频的通道 | 同上 |
| `SWAP_GUARD` | `none` / `llm`（多模态模型检查人脸） | mock 时 `none`，否则 `llm` |
| `SWAP_CHECK` | `auto` / `alter` / `basic` | `auto`（有 numpy + Pillow 就用 ALTER 质检） |
| `SWAP_BORG_IMAGE_MODEL` / `SWAP_BORG_VIDEO_MODEL` / `SWAP_BORG_VIDEO_SIZE` | 博观模型参数 | `image-2.5-flare` / `seedance-2.5` / `720p` |
| `SWAP_MAX_JOBS` | 同时提交的视频任务上限 | `3` |

例：`SWAP_PROVIDER=borg npm run dev`

**接一个新厂商**：在 `engine/providers/` 写一个文件，实现 `ImageEditor` 或 `VideoEditor`（`engine/types.ts`），再在 `engine/registry.ts` 的表里加一行。流水线和页面不用改。

## 做一个模板

```bash
npm run swap:template -- <id> <视频> --start 0 --end 10 --cover 0.5 --title 名称
```

然后编辑 `templates/<id>/template.json`：

- `who`：原片主角，**不要描述要换掉的那个东西**
- `frameAt`：从哪一秒取预览图的底图（主体最大、最清楚的一帧）
- `slot`：替换位，`preset` 从 `vendor/alter/references/presets.md` 选，`framePrompt` 是生成预览图的指令
- `versions`：附加版本，只能用不需要参考图的预设（风格化、时间、天气、年代……）

`npm test` 会检查每个模板的预设和填空是否齐全。

## 目录

```
engine/types.ts        四个接口 + 模板 / 任务的数据结构
engine/pipeline.ts     任务状态机（checking → framing → pick → rendering → done）
engine/registry.ts     按环境变量选实现
engine/presets.ts      读 ALTER 预设拼提示词
engine/media.ts        ffmpeg：取帧、合回原声、对比视频
engine/providers/      mock / borg / llmGuard / checkers
server.ts              Vite 中间件：/api/swap/*、/swap-files/*
web/                   用户页面
templates/             模板（每个一个文件夹）
data/                  任务和产物（不进仓库）
vendor/alter/          Scenario ALTER skill 原样拷贝
```
